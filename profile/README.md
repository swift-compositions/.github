# Swift Compositions

Use this organization when you want working systems rather than vocabulary: HTTP and networking, markup and serialization, cryptography and authentication, database connectivity, I/O and filesystem, rendering, observability, and platform integration. It is Layer 4 of the [Swift Institute](https://github.com/swift-institute), and it is where opinions live. Its packages build on [swift-atoms](https://github.com/swift-atoms), [swift-molecules](https://github.com/swift-molecules) and [swift-standards](https://github.com/swift-standards). If you only need a specification's types, use [swift-standards](https://github.com/swift-standards).

## Start here

- [swift-pdf](https://github.com/swift-compositions/swift-pdf): PDF documents, authored with a result-builder DSL
- [swift-html](https://github.com/swift-compositions/swift-html): type-safe HTML, CSS and SVG
- [swift-file-system](https://github.com/swift-compositions/swift-file-system): typed filesystem operations
- [swift-io-kernel](https://github.com/swift-compositions/swift-io-kernel): an async I/O executor that isolates blocking syscalls from the cooperative pool
- [swift-linter](https://github.com/swift-compositions/swift-linter): SwiftSyntax-based linting with SARIF output
